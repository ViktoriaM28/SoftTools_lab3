## Цель работы
Сколько времени занимает каждый этап: подтверждение оплаты, сборка у продавца, транспортировка? Где узкое место?

## Исследуемые метрики
- **Доля транспортировки** = `SUM([transit_days]) / SUM([total_days])`

## Архитектура решения
Kaggle (Olist, 9 CSV) → Python (`urllib`, `pandas`) → SQLite: RAW → STAGING → CORE → витрина `dm_v16_order_stages` → CSV → Yandex DataLens.

## Технологический стек
Python 3.13.18, pandas 2.2.3, SQLite 3.45.1, Google Colab / Jupyter, Yandex DataLens.

## Схема данных
Слои: `raw_*` (9 таблиц) → `stg_*` (типизация, очистка) → `core_order`, `core_item`, `dim_state` → `dm_v16_order_stages` (VIEW).


## SQL витрины
```sql
CREATE VIEW dm_v16_order_stages AS
SELECT order_id,
       purchase_month AS month,
       region,
       CASE weekday_num
           WHEN 1 THEN '1. Понедельник'
           WHEN 2 THEN '2. Вторник'
           WHEN 3 THEN '3. Среда'
           WHEN 4 THEN '4. Четверг'
           WHEN 5 THEN '5. Пятница'
           WHEN 6 THEN '6. Суббота'
           WHEN 0 THEN '7. Воскресенье'
       END AS weekday,
       (unixepoch(approved_ts) - unixepoch(purchase_ts)) / 3600.0 AS approval_hours,
       (unixepoch(carrier_ts) - unixepoch(approved_ts)) / 86400.0 AS handling_days,
       (unixepoch(delivered_ts) - unixepoch(carrier_ts)) / 86400.0 AS transit_days,
       (unixepoch(delivered_ts) - unixepoch(purchase_ts)) / 86400.0 AS total_days
FROM core_order
WHERE order_status = 'delivered'
```



## Результаты

1. По 96 478 доставленным заказам полный цикл занял в среднем 12,56 дня. Подтверждение оплаты занимало 10,28 часа, сборка — 2,80 дня, транспортировка — 9,33 дня. На транспортировку пришлось 74,3% суммарной длительности полного цикла.
2. На Севере перевозка занимала в среднем 19,25 дня, на Юго-Востоке — 7,54 дня. Разница в 11,71 дня существенно больше разницы в сборке (2,83 и 2,80 дня). Объёмы регионов различались: 1 796 и 66 200 доставленных заказов соответственно.
3. Оплата субботних заказов подтверждалась в среднем за 14,37 часа, а заказов среды — за 8,38 часа. Разница составила 5,99 часа при 10 555 заказах в субботу и 15 076 в среду.


## ИТОГ

Главное узкое место — транспортировка. От передачи перевозчику до получения заказа проходит в среднем 9,33 дня. На этот этап приходится 74,3% суммарного времени полного цикла.

## Сопоставление контрольных значений и ограничения

На полной витрине получены 2,80 дня сборки и 74,3% транспортировки. На подвыборке из 95 082 заказов с полным набором отметок в хронологическом порядке — 2,85 дня и 74,2%. Разница составляет 0,05 дня и 0,1 процентного пункта по округлённым значениям. Это сравнение двух способов обработки одного набора данных. Числовые эталоны в карточке варианта отсутствуют.

В витрине 1 350 отрицательных интервалов сборки и 23 отрицательных интервала перевозки. Они могут отражать порядок регистрации событий, а неизвестные интервалы остаются пустыми и исключаются из средних. Знаменатели средних различаются, поскольку отметки этапов отсутствуют у разных заказов. Доля перевозки — отношение сумм, поэтому длительные заказы сильнее влияют на результат. Учитываются только доставленные заказы. Регион определяется адресом покупателя, а длительность может зависеть от маршрутов, состава заказов и периода покупки.

| Диаграмма | Поля |
|---|---|
| Индикатор «Полный цикл, дн» | AVG([total_days]) |
| Столбчатая «Длительность этапов» | X — region; Y — AVG([handling_days]), AVG([transit_days]) |
| Круговая «Более длительный этап» | IF ISNULL([handling_days]) OR ISNULL([transit_days])
    THEN "Нет данных"
ELSEIF [handling_days] < 0 OR [transit_days] < 0
    THEN "Некорректные даты"
ELSEIF [transit_days] > [handling_days]
    THEN "Транспортировка"
ELSEIF [handling_days] > [transit_days]
    THEN "Сборка"
ELSE "Одинаковая длительность"
END
| Линейная «Этапы по месяцам» | X — month; Y — AVG([handling_days]), AVG([transit_days]) |
| Комбинированная «Подтверждение оплаты по дням недели» | X — weekday; столбцы — COUNT([order_id]); линия — AVG([approval_hours]) по дополнительной оси |
